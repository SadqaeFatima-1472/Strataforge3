THE PROBLEM

What happens after deployment, quietly

Whether it's transaction patterns shifting, applicant profiles changing, or customer behavior moving — the story is the same across fraud, credit, and claims models: the data your model sees stops looking like the data it was trained on, and nobody notices until it shows up as losses.

P0

Deployment baseline

Model trained and validated. Strong performance on held-out test data — the number everyone signs off on.

P1–2

Performance begins shifting

The patterns underneath start moving. Without something watching for it, this is completely invisible.

P3–4

Degradation compounds

Recall and precision drift in ways that still look fine in a monthly summary but aren't.

P5
Alert fires

Sentinel catches it here

Recall drops below your defined safety threshold. You get the alert — and the evidence record — before the losses compound further.

API ACCESS

Bring your own model's scores — we do the rest

You don't need to hand over your model. Send Sentinel the scores and labels it's already producing, and it handles drift detection, threshold optimization, and compliance evidence — isolated per model, so multiple teams or customers can run on the same account without touching each other's data.

# Register a model's baseline, then check for drift — POST /tenants/{model_id}/reference
import requests

requests.post(
    f"https://api.strataforge3.com/tenants/{model_id}/reference",
    headers={"Authorization": "Bearer <your_api_key>"},
    json={"data": baseline_rows, "labels": baseline_labels}
)

# Later, check today's batch against that baseline
response = requests.post(
    f"https://api.strataforge3.com/tenants/{model_id}/drift/report",
    headers={"Authorization": "Bearer <your_api_key>"},
    json={"transactions": todays_rows}
)

# Returns: alert level · drift score · which features moved, and by how much
data = response.json()
print(data["alert_level"], data["mean_psi"], data["critical_features"])
